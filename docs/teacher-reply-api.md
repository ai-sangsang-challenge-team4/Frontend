# 교사 답변 API 연동 (#54)

`VITE_MESSAGE_API=http`이면 서버 메시지함 스레드의 답변(AI 초안·임시저장·전송)을 백엔드 `/teacher/complaints/{id}` 답변 API로 처리합니다. mock 모드(기본)는 기존 로컬 답변 흐름(mock AI 초안, 브라우저 임시저장, 학부모 메시지 브리지 전송)을 그대로 씁니다. 조회 쪽은 [teacher-inbox-api.md](teacher-inbox-api.md)를 참고하세요.

## API

| 동작 | Method | Endpoint | 비고 |
| --- | --- | --- | --- |
| AI 초안 | POST | `/response/ai-draft` | 서버에 초안으로 저장되지 않음. 서버가 `AI_DRAFT_GENERATED` 이력을 남겨 생성 뒤 이력을 다시 불러옴 |
| 임시저장 조회 | GET | `/response-draft` | 답변 작성 화면에 처음 들어갈 때 세션당 한 번. 404 `RESPONSE_DRAFT_NOT_FOUND`는 "저장된 초안 없음" |
| 임시저장 | PUT | `/response-draft` | `{ content }`. 민원·교사당 초안 하나를 생성 또는 덮어씀 |
| 전송 | POST | `/responses` | `{ content }`. 저장된 초안이 답변이 되고 `waitingFor=PARENT`로 바뀜. 전송 뒤 상세·대화·이력을 다시 불러옴 |

`content`는 공백만으로 보낼 수 없고 1500자 이하입니다(`@NotBlank`, `@Size(max = 1500)`). 입력창은 1500자에서 막히고, 템플릿으로 만든 본문이 1500자를 넘으면 임시저장·전송을 막고 안내합니다. 이 제한은 mock 모드에도 적용합니다.

## 탭별 초안과 서버 단일 초안

화면은 탭마다 초안을 보관하지만(AI 초안 활용·직접 작성, High는 AI 탭의 답장 예시) 서버는 민원당 초안 하나만 가집니다.

- **임시저장은 현재 탭 내용만** 서버에 저장합니다. 저장하면 다른 탭의 "마지막 임시저장" 표시를 지웁니다(서버 사본이 아니게 되므로). 탭 상태는 브라우저 메모리에만 남습니다.
- **복원**: 답변 작성 화면에 처음 들어가면 서버 초안을 조회합니다. 이 세션에서 작성한 탭이 없으면 서버 초안을 **직접 작성 탭**으로 복원하고 그 탭을 엽니다(기존 정책 "작성하던 답변은 직접 작성 탭으로 이어짐"과 같음). 브라우저에 작성 중인 탭이 있으면 그쪽이 더 최신이라 서버 초안을 쓰지 않습니다.
- High에서 맞는 답장 예시가 있으면 직접 작성 탭이 닫혀 있고, 평문 초안을 예시의 빈칸·문장으로 되돌릴 수 없어 복원하지 않습니다. 이때 "예시를 다시 적용해 주세요" 안내를 띄웁니다.
- **AI 초안**: Low·Medium에서 AI 탭을 한 번도 채운 적이 없고 복원한 초안도 없으면 진입 시 한 번 자동으로 요청합니다. 실패했거나 초기화로 비운 AI 탭에는 "AI 초안 생성" 버튼이 나타납니다. 응답이 도착했을 때 AI 탭에 이미 작성한 내용이 있으면 덮어쓰지 않습니다.
- 서버 모드의 AI 초안은 백엔드가 만들므로 프론트 RAG 검색 결과(규정 없음)로 막지 않습니다. 참고자료 패널과 출처 표시는 프론트 전용 예시로 그대로 보입니다.
- **초기화**는 화면의 현재 탭만 비웁니다. 서버 초안 삭제 API가 없어 서버 초안은 다음 임시저장 때 덮어쓰기 전까지 남고, 새로고침 뒤 다시 복원될 수 있습니다.
- "임시저장 답변" 목록 탭과 초안 이어쓰기 안내는 브라우저에 있는 초안 기준입니다. 서버에만 있는 초안은 답변 작성 화면에 들어가야 보입니다.

요청 중(초안 불러오기·AI 초안 생성·임시저장·전송)에는 상태 문구를 표시하고 입력과 버튼을 막습니다. 요청은 한 번에 하나만 보냅니다.

## 차단

- **안전 잠금·긴급 단계·분석 확인 전**: 기존과 같이 화면에서 작성·전송 UI를 잠그고, AI 초안·임시저장·전송 요청 직전에도 다시 확인합니다. **백엔드는 위험도로 답변을 막지 않고** `OPEN`·`waitingFor=TEACHER`만 확인하므로 이 차단은 프론트가 책임집니다.
- **서버가 답변을 받지 않는 상태**: `waitingFor`가 `TEACHER`가 아니면(학부모 답장 대기, 상담 완료) 안내 문구를 표시하고 입력·임시저장·전송을 막습니다. 분석이 로딩 중이면 로드가 끝난 뒤 초기화합니다.
- 상담 완료는 백엔드 API가 없어 서버 스레드에서는 계속 막혀 있습니다.

## 오류 처리

| 코드 | 화면 |
| --- | --- |
| `RESPONSE_NOT_EDITABLE` (409) | "지금은 답변할 수 없는 문의예요…" 안내 후 상세를 다시 불러와 현재 상태(학부모 차례·완료)를 반영 |
| `RESPONSE_DRAFT_NOT_FOUND` (404) | 초안 조회에서는 "초안 없음"으로 처리, 안내하지 않음 |
| `VALIDATION_FAILED` (400) | 서버 메시지 그대로 표시 |
| 그 외 | 동작별 기본 문구(전송은 `REPLY_SEND_FAILED_MESSAGE`). 작성 중인 초안은 유지되어 다시 시도 가능 |

전송이 실패하면 중복 전송 방지 키를 풀어 같은 내용으로 다시 보낼 수 있습니다.

## 백엔드 확인·요청

- 답변 API가 위험도·안전 잠금을 확인하지 않습니다. EMERGENCY·잠금 상태에서 AI 초안·저장·전송을 서버에서도 막아 주세요(`allowedActions`에 `USE_RESPONSE_TEMPLATE`이 없는 상태).
- 서버 초안을 지우는 API가 없어 화면의 초기화가 서버에 반영되지 않습니다.
- 초안 응답에 어느 탭(AI·직접 작성·템플릿)에서 저장했는지가 없어 복원은 항상 직접 작성 탭입니다. 템플릿 초안을 복원하려면 템플릿 ID·입력값 저장이 필요합니다.
- AI 초안 생성기는 아직 Mock이라 항상 같은 문장이 옵니다.

## 코드

- `api/httpTeacherInboxApi.ts`: `generateAiDraft`, `getResponseDraft`, `saveResponseDraft`, `submitResponse`
- `serverReplies.ts`: 탭 ↔ 서버 초안 매핑(`restoreServerDraft`, `markServerDraftSaved`, `setReplyDraftTabState`), 전송 응답 반영(`applyServerSubmission`), 답변 가능 상태(`getServerReplyBlockReason`)
- `useServerReply.ts`: 요청 순서·중복 방지·오류 처리. `TeacherMessages.tsx`의 초기화·임시저장·전송 핸들러가 서버 스레드일 때 이 훅으로 넘깁니다.

## 테스트

```bash
npx playwright test teacher-reply-api
```

`teacher-reply-api.spec.ts`는 fetch를 대체해 요청 경로·메서드·본문, 409/404 오류 구분, 탭 ↔ 서버 초안 매핑, 전송 응답 반영을 확인합니다. 실제 서버 호출은 아닙니다. 기존 mock 답변 흐름은 `teacher-reply-flow.spec.ts`가 그대로 확인합니다.
