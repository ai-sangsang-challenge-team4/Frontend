# 교사 답변 API 연동 (#54)

`VITE_MESSAGE_API=http`이면 서버 메시지함 스레드의 답변(AI 초안·임시저장·전송)을 백엔드 `/teacher/complaints/{id}` 답변 API로 처리합니다. mock 모드(기본)는 기존 로컬 답변 흐름(mock AI 초안, 브라우저 임시저장, 학부모 메시지 브리지 전송)을 그대로 씁니다. 조회 쪽은 [teacher-inbox-api.md](teacher-inbox-api.md)를 참고하세요.

Low·Medium은 메시지 상세에서 답변 작성 버튼을 누르면 대화 아래에 기존 작성 패널을 엽니다. `/response` 주소와 뒤로 가기·이어쓰기는 유지하며, 원문·요약 표시와 열람 권한은 대화 화면의 기존 정책을 따릅니다. High는 별도 작성 화면을 유지합니다. 화면 배치만 변경하며 초안 조회·생성·저장·전송 API, 안전 잠금, 답변 차례, 1500자 제한과 최종 전송 확인은 동일합니다.

문의 상세의 상단 카드는 발신자·원래 문의 제목·기존 분석 상태를 표시하며, API에서 제공한 문의 요약은 제목 아래에 표시합니다. 요약이 없는 서버 문의에는 요약 문구를 임의로 채우지 않으며, 최근 수신 시각은 생략합니다. 별도 답변 작성 화면의 카드는 기존 표시를 유지합니다. 별도의 대화 제목·표시 안내 툴팁 없이, 대화창 하단에서 답변 작성 버튼 왼쪽에 배치한 “AI 분석 근거” Outline 버튼은 현재 화면의 Drawer를 엽니다. 답변 편집 중에는 같은 버튼을 선생님 답변 헤더의 닫기 버튼 왼쪽으로 옮기고 채팅 하단에서는 제거합니다. 편집기를 닫으면 하단으로 돌아오며, 기존 열림 상태와 같은 클릭 핸들러를 재사용해 한 번만 표시합니다. 답변 제한 상태에서는 기존 하단 위치를 유지합니다. 개폐 자체로 API를 호출하거나 초안을 초기화하지 않습니다. 1600px 이상은 본문 옆 패널, 그 미만은 포커스를 유지하는 Drawer, 모바일은 전체 너비를 사용합니다. 규정 상세는 기존 모달로 확인합니다. 분석 상태가 ready가 아니면 하단 분석 근거 버튼을 비활성화하며, 원문 열람과 답변 잠금 정책은 변경하지 않습니다. High·Emergency의 안전 정책은 유지합니다.

대화 영역은 최소 240px에서 내용에 맞춰 늘어나며 페이지 전체를 스크롤합니다. 마지막 메시지와 답변 CTA 간격은 24px입니다. 답변 작성 참고사항은 작성 패널 아래에서 기본 접힘으로 표시하고, 펼치면 기존 주의 포인트·작성 가이드·RAG 근거를 확인할 수 있습니다. 펼침 여부는 초안과 API 처리에 영향을 주지 않습니다. 답변 필요 문구(하단 미답변 배지 생략)와 제공된 분석의 AI 판단 안내는 왼쪽에, 분석 근거·답변 작성 버튼은 오른쪽에 12px 간격으로 나란히 배치합니다. 하단 분석 근거·답변 작성은 공통 Button md(최소 47px, 16px) 규격과 동일한 너비를 사용합니다. 편집기 헤더의 분석 근거·닫기도 md와 12px 간격을 사용하며, 620px 이하에서는 헤더 제목 아래로 버튼 그룹을 배치합니다. 모바일에서는 안내 아래에 두 버튼을 같은 높이로 배치합니다. 분석 대기·진행 중에는 하단의 중복 상태 문구를 생략하되 기존 답변 제한 안내는 유지합니다. 분석 실패는 하단에도 명시적으로 표시하며, 결과가 제공되면 AI 판단 안내의 툴팁으로 상세 설명을 제공합니다. 입력창 바로 아래에는 14px 검토 안내를 표시하며, 실제 AI 생성 표시와 비어 있지 않은 AI 탭 초안이 있을 때만 AI 초안 검토 문구를 사용합니다. 직접 작성·빈 초안·공식 템플릿은 일반 검토 안내를 표시합니다. 분석 실패·답변 생성 실패·안전 잠금 안내는 기존 분리된 상태를 유지합니다.

대화 원문과 메시지별 요약은 기존 표시 정책에 따라 보존합니다. 역할·발신자 이름이 같고 같은 날짜에 30분 이내로 이어지는 메시지는 첫 메시지에만 프로필을 표시합니다. API가 발신자 ID를 제공하지 않아 현재 역할·이름을 사용하며, 시간이 없거나 잘못되었거나 역순이면 별도 그룹으로 표시합니다. 메시지를 재정렬하거나 데이터를 수정하지 않습니다. 메시지별 시간이 없는 기존 통합 완충 요약 화면은 그룹화를 적용하지 않습니다.

브라우저 mock 규정 조회가 not_found인 Low·Medium 문의는 직접 작성 탭으로 초기화합니다. 기존 탭별 초안은 보존하며 AI 탭 선택 시 입력 제한은 유지합니다. 서버 초안의 조회·생성 정책, High 템플릿과 Emergency 잠금은 변경하지 않습니다.

## API

| 동작 | Method | Endpoint | 비고 |
| --- | --- | --- | --- |
| AI 초안 | POST | `/response/ai-draft` | 서버에 초안으로 저장되지 않음. 서버가 `AI_DRAFT_GENERATED` 이력을 남겨 생성 뒤 이력을 다시 불러옴 |
| 임시저장 조회 | GET | `/response-draft` | 답변 작성 화면에 처음 들어갈 때 세션당 한 번. 404 `RESPONSE_DRAFT_NOT_FOUND`는 "저장된 초안 없음" |
| 임시저장 | PUT | `/response-draft` | `{ content }`. 민원·교사당 초안 하나를 생성 또는 덮어씀 |
| 전송 | POST | `/responses` | `{ content }`. 저장된 초안이 답변이 되고 `waitingFor=PARENT`로 바뀜. 전송 뒤 상세·대화·이력을 다시 불러옴 |
| High 템플릿 조회 | GET | `/response-templates` | 위험 단계(교사 검토 반영)이고 잠금이 아닐 때만, 답변 작성 화면에 처음 들어가면 세션당 한 번. 서버 초안 복원보다 먼저 불러옴(템플릿이 있으면 직접 작성 탭이 닫히므로) |
| 템플릿 채택 기록 | POST | `/response-templates/{versionId}/adoptions` | `{ variables, finalContent }`. 서버 템플릿으로 만든 답변을 보낼 때 `/responses` 직전에 호출. 실패하면 답변을 보내지 않음. 같은 내용으로 재전송하면 다시 기록하지 않음 |

서버 스레드는 브라우저 예시 템플릿 대신 서버 템플릿만 씁니다. 서버 템플릿은 `{{변수}}`가 들어간 한 문장 영역으로 바꿔 기존 제한형 편집기에 띄우며, 교사는 `requiredVariables`의 빈칸만 채웁니다(`parentName`·`issueSummary`는 학부모 호칭·문의 주제로 미리 채움). 조회가 실패하면 안내 후 직접 작성 탭을 씁니다.

`content`는 공백만으로 보낼 수 없고 1500자 이하입니다(`@NotBlank`, `@Size(max = 1500)`). 입력창은 1500자에서 막히고, 템플릿으로 만든 본문이 1500자를 넘으면 임시저장·전송을 막고 안내합니다. 이 제한은 mock 모드에도 적용합니다.

## 탭별 초안과 서버 단일 초안

화면은 탭마다 초안을 보관하지만(AI 초안 활용·직접 작성, High는 AI 탭의 답장 예시) 서버는 민원당 초안 하나만 가집니다.

- **임시저장은 현재 탭 내용만** 서버에 저장합니다. 저장하면 다른 탭의 "마지막 임시저장" 표시를 지웁니다(서버 사본이 아니게 되므로). 탭 상태는 브라우저 메모리에만 남습니다.
- **복원**: 답변 작성 화면에 처음 들어가면 서버 초안을 조회합니다. 이 세션에서 작성한 탭이 없으면 서버 초안을 **직접 작성 탭**으로 복원하고 그 탭을 엽니다(기존 정책 "작성하던 답변은 직접 작성 탭으로 이어짐"과 같음). 브라우저에 작성 중인 탭이 있으면 그쪽이 더 최신이라 서버 초안을 쓰지 않습니다.
- High에서 맞는 답장 예시가 있으면 직접 작성 탭이 닫혀 있고, 평문 초안을 예시의 빈칸·문장으로 되돌릴 수 없어 복원하지 않습니다. 이때 "예시를 다시 적용해 주세요" 안내를 띄웁니다.
- **AI 초안**: Low·Medium에서 AI 탭을 한 번도 채운 적이 없고 복원한 초안도 없으면 진입 시 한 번 자동으로 요청합니다. 실패했거나 초기화로 비운 AI 탭에는 "AI 초안 생성" 버튼이 나타납니다. 응답이 도착했을 때 AI 탭에 이미 작성한 내용이 있으면 덮어쓰지 않습니다.
- 서버 모드의 AI 초안은 백엔드가 만들므로 참고자료 없음으로 생성을 막지 않습니다. `POST /response/ai-draft`의 `references`만 관련 규정 및 근거에 표시하며, 빈 배열·누락·null이면 "관련 참고자료가 없습니다."를 표시합니다. 로컬 예시 규정으로 대체하지 않습니다.
- 참고자료의 `source`, `page`, `content`를 표시합니다. 페이지가 null이면 정보 없음을 표시하고, 자세히 보기는 검색된 문단 전체를 보여줍니다. 문서 전체 원문이나 제공되지 않은 기관·버전·링크를 추정하지 않습니다.
- 참고자료는 생성된 AI 탭 초안과 함께 메모리에 보관합니다. 탭 전환·편집기 개폐·저장 시 유지하고, AI 탭 초기화·전송 시 제거합니다. 재생성 시 새 응답으로 교체합니다. 임시저장 API는 `content`만 받으므로 새로고침 후 복원한 초안에는 참고자료가 없으며, 복원을 위해 AI 생성을 추가 호출하지 않습니다.
- 배포 Swagger에서 `TeacherAiDraftResponse.references`와 `RagReference` 계약을 확인했습니다. 응답의 `legalCitationWarning: true`는 해당 AI 탭 초안 아래에 법령 인용 검토 안내로 표시합니다. 탭 전환·개폐·저장 시 보존하고, 초기화·공식 템플릿 적용·전송 시 제거합니다. false·누락 및 직접 작성 탭에서는 표시하지 않으며 기존 전송 조건은 바꾸지 않습니다.
- **초기화**는 화면의 현재 탭만 비웁니다. 서버 초안 삭제 API가 없어 서버 초안은 다음 임시저장 때 덮어쓰기 전까지 남고, 새로고침 뒤 다시 복원될 수 있습니다.
- "임시저장 답변" 목록 탭과 초안 이어쓰기 안내는 브라우저에 있는 초안 기준입니다. 서버에만 있는 초안은 답변 작성 화면에 들어가야 보입니다.

요청 중(초안 불러오기·AI 초안 생성·임시저장·전송)에는 상태 문구를 표시하고 입력과 버튼을 막습니다. 요청은 한 번에 하나만 보냅니다.

## 차단

- **안전 잠금·긴급 단계·분석 확인 전**: 기존과 같이 화면에서 작성·전송 UI를 잠그고, AI 초안·임시저장·전송 요청 직전에도 다시 확인합니다. 현재 Swagger는 백엔드도 EMERGENCY·`safetyLock`에서 생성·저장·전송을 차단한다고 명시합니다. Low·Medium은 AI 초안, High는 제한형 공식 템플릿을 사용합니다.
- **서버가 답변을 받지 않는 상태**: `waitingFor`가 `TEACHER`가 아니면(학부모 답장 대기, 상담 완료) 안내 문구를 표시하고 입력·임시저장·전송을 막습니다. 분석이 로딩 중이면 로드가 끝난 뒤 초기화합니다.
- 학부모 차례·완료 상태에서는 메시지 상세의 답변 안내도 "지금은 답변할 차례가 아닙니다"로 바뀌고 답변 작성 버튼을 숨깁니다.
- 답변 전송 후 `ANSWERED / PARENT`가 되며 학부모가 문의를 완료하거나 추가 문의를 작성할 수 있습니다.

## 오류 처리

| 코드 | 화면 |
| --- | --- |
| `RESPONSE_NOT_EDITABLE` (409) | "지금은 답변할 수 없는 문의예요…" 안내 후 상세를 다시 불러와 현재 상태(학부모 차례·완료)를 반영 |
| `RESPONSE_DRAFT_NOT_FOUND` (404) | 초안 조회에서는 "초안 없음"으로 처리, 안내하지 않음 |
| `VALIDATION_FAILED` (400) | 서버 메시지 그대로 표시 |
| 그 외 | 동작별 기본 문구(전송은 `REPLY_SEND_FAILED_MESSAGE`). 작성 중인 초안은 유지되어 다시 시도 가능 |

시간 초과·네트워크·5xx처럼 전송 성공 여부가 불확실하면 같은 민원·본문의 재시도에 기존 `Idempotency-Key`를 재사용합니다. 성공 응답이나 4xx 거부 응답을 받은 뒤에는 키를 정리합니다.

## 백엔드 확인·요청

- 배포 Swagger는 답변 API의 EMERGENCY·안전 잠금 차단을 명시합니다. 프론트도 기존 차단을 유지하며 서버의 거부 응답을 처리합니다.
- 서버 초안을 지우는 API가 없어 화면의 초기화가 서버에 반영되지 않습니다.
- `POST /adoptions`는 201을 주지만 Swagger에는 200으로 나옵니다. 템플릿이 HIGH가 아닌 민원은 빈 배열이 아니라 409이고, 안전 잠금 중 조회는 차단 이력을 남기므로 프론트는 위험 단계·잠금이 아닐 때만 조회합니다.
- 초안 응답에 어느 탭(AI·직접 작성·템플릿)에서 저장했는지가 없어 복원은 항상 직접 작성 탭입니다. 템플릿 초안을 복원하려면 템플릿 ID·입력값 저장이 필요합니다.
- Backend의 `PythonTeacherSupportContentProvider`는 Python AI의 `/api/v1/ai/response-draft`를 호출합니다. 아래 Mock 초안 수동 확인은 2026-10-29 당시 기록이며 현재 AI 연결 검증을 대신하지 않습니다.

- `useServerReply.ts`: 요청 순서·중복 방지·오류 처리. `TeacherMessages.tsx`의 초기화·임시저장·전송 핸들러가 서버 스레드일 때 이 훅으로 넘깁니다.

## 테스트

```bash

```

### 배포 서버 수동 확인 (2026-10-29)

로컬 개발 서버(http 모드, 프록시 `https://teacherhub.duckdns.org`)와 dev 계정으로 확인했습니다. 학부모 문의 작성은 아직 프론트가 서버에 연결되지 않아, 테스트 민원(complaintId 2, "[테스트] #54 답변 연동 확인")은 학부모 API(`POST /complaints` → `/risk-analysis` → `/send`)로 직접 만들었습니다. 서버 분석기가 Mock이라 평범한 문의도 HIGH(위협 탐지)로 나와, 교사 위험도 검토로 2점(LOW)으로 낮춘 뒤 AI 초안 경로를 확인했습니다.

| 확인 | 결과 |
| --- | --- |
| 첫 진입 `GET response-draft` 404 | 오류 안내 없이 "작성 중인 답변 없음". High라 AI 초안 요청 없음 |
| 직접 작성 → 임시저장 | `PUT` 200, "마지막 임시저장" KST 표시 |
| 새로고침·재로그인 후 진입 | 서버 초안이 직접 작성 탭에 저장 시각과 함께 복원 |
| LOW로 낮춘 뒤 비어 있는 AI 탭 | 자동 생성 없이 "AI 초안 생성" 버튼, 누르면 "AI 초안을 만드는 중…" 동안 버튼 잠금 → `POST ai-draft` 201, Mock 초안 표시, 처리 기록에 "AI 답변 초안 생성" |
| AI 탭 임시저장 | `PUT` 200, 직접 작성 탭은 저장 표시가 사라지고 "작성 중" |
| 1600자 입력 | 1500자에서 잘림 |
| 검토 후 전송 | `POST responses` 201, 전송 완료 창, 대화에 답변 추가, 목록 "상담 중", 처리 기록 "메시지 전송" |
| 전송 뒤 다시 답변 작성 | 요청 없음, 입력·버튼 비활성, "학부모의 답장을 기다리는 중…" |

수동 확인으로 찾아 고친 것: 전송 뒤 메시지 상세가 계속 "답변 작성이 필요합니다"로 보이던 문제, 서버 모드 참고자료 패널의 "AI 초안을 생성하지 않습니다" 문구.
