# 개인정보 마스킹 및 안전 상태 UI (#13)

학부모 문의 작성·검토 화면에 기존 전화번호·이메일 마스킹을 연결하고, 교사 메시지 화면의 안전 안내와 재검토 흐름을 보완합니다. 공통 `Button`, `Badge`, `Modal`, 기존 메시지 상태·대응 가이드·처리 기록을 재사용합니다.

## 학부모 화면

- 제목·본문 입력 시 개인정보 탐지 건수와 접을 수 있는 마스킹 결과를 표시합니다. 탐지한 값은 `[전화번호]`, `[이메일]`, `[주민등록번호]`, `[이름]`으로 표시합니다.
- AI 분석에는 마스킹된 본문만 사용합니다. 원문은 직접 비교·수정할 수 있도록 기존 초안에 유지합니다.
- 선택한 AI 초안이나 원문을 수정하면 마스킹 결과도 갱신합니다. 확인창에서 전송할 제목과 최종 본문을 확인할 수 있습니다. 수정할 수 없는 서버 제목에 개인정보가 있으면 확인창이 실제 제목과 새 문의 작성 방법을 안내합니다.
- 마스킹 실패는 AI 수정안 생성 실패와 구분합니다. 마스킹 실패 시 검토 화면으로 넘어가지 않고 분석·전송 버튼을 비활성화합니다. 입력 유지, 직접 수정, 마스킹 재시도를 제공합니다.
- 마스킹에 성공한 뒤 AI 수정안 생성만 실패한 경우에는 기존의 원문 확인·전송 흐름을 유지합니다.
- AI 판단이 참고 정보임을 검토 화면에 표시합니다.

## 교사 화면

- 기존 Emergency 안내와 공식 절차 링크를 사용합니다. 긴급 단계 또는 `safetyLock` 상태에서는 답변 생성·전송 제한이 유지됩니다.
- 긴급 단계가 아닌 `safetyLock`도 별도 문구로 안내합니다. 위험도 수정이나 재검토 요청 자체로는 잠금이 해제되지 않습니다.
- 긴급 하향은 점수와 사유를 입력한 뒤 `재검토 요청` 하나로 저장합니다. 실제 접수 후 비활성화된 `검토자 확인 대기` 버튼을 표시하고, 실패 시 입력을 유지하며 재시도를 제공합니다. 로컬 접수 표시만 남기던 별도 재검토 버튼과 상태는 제거했습니다. 위험도를 수정할 권한이 없으면 요청도 접수하지 않습니다.
- `studentSafetySignal`의 `NONE`은 카드를 숨기고, `POSSIBLE`은 추가 확인, `URGENT_REVIEW`는 긴급 확인 문구와 배지를 표시합니다. 관련 원문 열람은 기존 권한 검사를 따릅니다.
- 답변 작성 화면에 AI 판단이 참고 정보임을 표시합니다.

## Mock 환경 및 연동 범위

프론트는 로컬 규칙으로 전화번호(휴대·일반·인터넷 전화와 050 개인 가상번호), 이메일, 주민등록번호를 가립니다. 학부모 문의 작성·검토에서는 확인된 학부모·자녀·교사 이름과 `이름: 김민수`, `성명: 김민수`처럼 표시한 한글 이름도 가립니다. 제목과 본문을 서버에 처음 저장할 때 이 규칙을 적용하고, 이후 분석이나 전송에 앞서 수정한 본문에도 다시 적용합니다. 이미 서버에 저장한 제목은 기존 API에서 수정할 수 없습니다. `pii-masking.spec.ts`에서 전화번호 등 백엔드 규칙과의 호환성을 확인합니다.

HTTP 모드에서 새 문의의 `마스킹 결과 보기`를 열면 자녀·문의 대상·제목·본문이 입력된 초안을 저장하고 기존 `POST /complaints/{complaintId}/mask`를 호출합니다. 같은 학급 학생 이름이 가려진 결과가 작성 화면에 표시됩니다. 서버에 초안이 만들어지면 자녀·문의 대상·제목이 확정됩니다. 미리보기를 열어 둔 채 본문을 수정하면 같은 초안의 마스킹 결과가 갱신됩니다. 필수값을 입력하는 동안에는 브라우저의 마스킹 결과가 표시됩니다. `AI 분석 시작`도 같은 초안을 사용합니다. AI 수정안은 서버가 복원한 내용으로 표시합니다. 추가 문의는 기존 메시지 분석 요청에서 서버가 마스킹합니다.

안전 상태는 기존 `ThreadAnalysis`와 서버의 재검토·공유 상태를 함께 사용합니다. HTTP 모드의 긴급 하향은 `POST /teacher/complaints/{complaintId}/emergency-review`로 요청하고 `GET …/emergency-review/current`로 상태를 복원합니다. Mock 모드에서는 같은 어댑터 계약으로 `teacher-hub.emergency-reviews.v2`에 저장합니다. 최신 서버 계약과 같이 하향 승인 시 위험도와 잠금 해제가 함께 반영되며, 반려 시 잠금이 유지됩니다. 화면은 응답의 `safetyLock`을 따르고 승인 상태만으로 해제를 추정하지 않습니다. 짧은 답변 제한 안내는 항상 본문에 두고 요청·승인 절차의 상세 설명만 공통 InformationTooltip에 표시합니다.

개발 서버에서 마스킹 실패는 브라우저 콘솔로 재현할 수 있습니다.

```js
localStorage.setItem('teacher-hub.pii-mock-settings', JSON.stringify({ failMasking: true }));
```

문의 작성 화면에서 `AI 분석 시작` 또는 검토 화면에서 `전송하기`를 누릅니다. 실패 상태와 차단을 확인한 뒤 아래 설정을 실행하고 `마스킹 다시 시도`를 누르면 복구합니다. 이 설정은 개발 모드에서만 적용됩니다.

```js
localStorage.removeItem('teacher-hub.pii-mock-settings');
```

## 검증

```bash
npm run build
npm run lint
npm run test:auth -- privacy-safety.spec.ts parent-message-review.spec.ts parent-message-write.spec.ts teacher-message-board.spec.ts teacher-reply-flow.spec.ts
```

`privacy-safety.spec.ts`는 제목·본문 마스킹, 분석 입력 보호, 수정 후 재검사, 확인창을 연 뒤 발생한 마스킹 실패, 실패 복구, Emergency·안전 잠금, 중복 재검토 요청, 학생 안전 신호 세 상태를 데스크톱·모바일에서 확인합니다.
