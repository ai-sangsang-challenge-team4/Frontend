# 교사 답변 예시 편집

PM의 `High_제한형_템플릿_화면 (1).pdf`를 기준으로 High 답변을 다섯 문장 영역으로 구성합니다. 인사에서는 허용된 빈칸만 입력하고, 문의 확인 문장은 150자 이내로 고칩니다. 원칙 안내와 마무리는 수정할 수 없으며 다음 안내는 라디오로 하나를 고릅니다. 교사 화면에는 개발용 영역 이름이나 유형을 표시하지 않습니다.

디자인은 기존 `상상챌린지/답변 작성.png`와 프로젝트의 교사 화면 스타일을 기준으로 합니다. 흰색 입력창, 회색 테두리, 파란색 강조색과 기존 공통 Dropdown·Badge·Button·Modal을 사용합니다. PM 문서는 기능과 편집 범위만 참고합니다.

상담 일시는 날짜·시간 선택기로 입력하며 `YYYY-MM-DDTHH:mm` 값으로 저장합니다. 답변에는 한국 시간 기준의 날짜·오전/오후·시간을 표시합니다. 날짜가 잘못되었거나 일시가 비어 있으면 해당 안내를 전송할 수 없습니다. 예전 자유 입력 값은 날짜 선택기에서 다시 선택해야 하며, 다른 안내를 고른 경우 상담 일시는 필수가 아닙니다.

`replyTemplates.ts`의 `ReplyTemplateDraft`는 입력한 빈칸, 직접 고친 문장, 선택한 안내를 보관합니다. `draftText`는 이 값과 고정 문장으로 생성합니다. 전송 직전에는 필수 입력, 글자 수, 선택값, 활성 버전과 생성된 본문의 일치를 다시 검사합니다. 선택하지 않은 안내의 빈칸은 검사하지 않습니다. 같은 예시의 새 버전을 적용하면 같은 입력 키와 문장 ID의 값을 유지합니다. 적용한 예시 정보는 학부모 문의의 `teacherReplyTemplate`에 함께 저장합니다.

일치하는 활성 예시가 없으면 직접 작성할 수 있습니다. Emergency에서는 작성·전송 UI 대신 공식 절차 안내를 표시하고 기존 전송 핸들러에서도 잠금을 확인합니다. 주의 표현은 경고와 수정 제안을 제공하며 전송을 막지는 않습니다. PDF에서 팀 결정으로 남긴 사람 검토 요청과 관리자 알림은 추가하지 않습니다.

RAG 출처마다 원문 확인 모달을 열어 문서 제목, 기관, 버전, 해당 조항을 표시합니다. 현재 코퍼스와 본문은 **화면 확인용 예시**이며 실제 학교 규정이 아닙니다. 외부 원문이 제공되면 `RegulationSource.url`로 연결할 수 있습니다. 예시 자료에는 외부 링크를 표시하지 않으며, 구버전 자료에는 별도 안내를 표시합니다. 검색·AI 생성·전송의 실제 API 연동은 기존과 같이 별도 작업입니다.

검증:

```sh
npm run build
npm run test:auth -- tests/auth/teacher-reply-flow.spec.ts tests/auth/reply-template-rules.spec.ts tests/auth/parent-message-history.spec.ts
```
